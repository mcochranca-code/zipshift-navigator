# Stanislaus County Intake Digitization Scope

## Scope

ZipShift digitizes the minimum information required to route a client to a verified Stanislaus County community resource. The current intake path covers contact preference, situation narrative, requested service categories, consent, accessibility accommodations, provider destination selection, referral confirmation, and structured access feedback. Staff-only YellowBook encounter fields remain protected and are not exposed in the client intake.

## Source provenance

Provider identity, service categories, operating hours, service days, address, phone, accessibility, document requirements, transit feasibility, and verification status are sourced from the canonical provider directory and the attached Drive operating-schedule export. The Drive-derived screenshots are workflow references only; their visual styling is not imported. Any provider record marked for confirmation remains visibly flagged for staff verification before it is treated as current.

## Privacy and retention boundaries

ZipShift does not collect IP addresses for ZIP demand reporting. Covered ZIP activity is stored only as a daily aggregate with small-cohort suppression. Client case data is stored under the authenticated account or as a case record created with explicit consent. Narrative fields are optional and should contain client-stated information only. Researchers receive de-identified or role-appropriate data for HSAI adjudication, while staff encounter details remain protected by workspace role checks.

## Deferred source work

A future county-approved intake-form import may add form-specific questions, translations, eligibility attestations, and agency-specific consent language. Before those fields are activated, the county form version, effective date, owning agency, retention rule, and accessibility review must be recorded in this document and in the directory provenance metadata.
